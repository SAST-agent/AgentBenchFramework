# Trajectory KL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a strict, end-to-end trajectory-KL path that measures two policy versions on the new policy's actual rollout, preserves first-hand decision data, and reports per-episode trajectory KL with correct units.

**Architecture:** A game runtime supplies a finite `ActionSupport` with stable action IDs. A `TrajectoryKLAgent` wrapper asks the active policy for one coherent action-plus-distribution decision, asks the reference policy for a distribution on the same support, executes only the active action, and advances both sessions with the same environment transitions. Tracking stores aligned action IDs and raw distributions; reporting derives the per-episode sum as primary and the per-decision mean as auxiliary.

**Tech Stack:** Python 3.11+, dataclasses, protocols, JSONL tracking, Jinja2 local report, unittest/pytest.

## Global Constraints

- Work only in the existing `/home/wkj/projects/AgentBenchFrame/.worktrees/framework` linked worktree.
- Do not implement historical replay-based KL or create another worktree.
- The measurement rollout is generated by the new policy; the direction is `KL(new || old)` with natural logarithms.
- A single fixed `0 < epsilon < 1` is applied to both policies only in the measurement layer.
- Legal action support is finite, complete, non-empty, ordered, duplicate-free, and identified by stable string action IDs plus a non-empty action-schema version.
- Policy distributions are mappings whose keys exactly equal the action support. The framework never infers HL probabilities; an HL adapter returns its own one-hot distribution.
- The active policy returns selected action ID and its distribution in one call. The old policy is comparison-only and receives the same actual transitions.
- `trajectory_kl_episode = sum(local_policy_kl_trace)` is primary in `nats / episode`; `mean_local_policy_kl` is auxiliary in `nats / decision`.
- Any missing/invalid decision measurement makes the episode measurement `incomplete`; no partial scalar is presented as the primary trajectory KL.
- Existing non-scientific `act()` agents and legacy policy-KL events remain readable.
