 # SnakeGo 迭代报告 · 第 1 轮（v1 → v2 → v3）

 ## 底层（本轮先打通，否则无法迭代）

 1. 用 MinGW g++ 15.2 把 7 个 adk.hpp 人类选手编译为静态 exe（自带运行时 DLL）。
 2. 把 `adk.hpp` 的 `Context` 游戏引擎逐行移植为 Python `snakego/engine.py`，与 C++ 引擎位级一致。
 3. 发现 Windows 下 `getchar()` 走文本模式，遇到字节 `0x1A`(Ctrl-Z) 误判为 EOF，导致 stdio 通道丢字节。改为 **socket 通道**（adk.hpp 的 `socket_channel(host,port)`，Winsock 是真二进制），彻底绕开该 bug。
 4. 实现 `snakego/host.py`：道具生成（逐行移植裁判 `spawn.py`）、字节协议中转、对战记录。
 5. 人类 vs 人类已跑通 5 场（不弱化），例如 rank09 vs rank15 → [98,74]，rank11 vs rank13 → [100,50]。

 ## 我的策略迭代（核心交付）

 所有版本是纯函数 `decide(engine, my_id) -> 操作码`，通过 `PythonPlayer` 接入同一套对战主机，与编译后的人类 exe 公平对战（双方都看完整棋盘）。

 ### v1：生存优先 baseline
 - 逻辑：过滤致死方向 → 贪心吃增长道具 → 否则走可达空间最大的方向。
 - 结果：**全败**。对 sample_ai [16,104]；对 rank15 [2,168]。只活 43 步就把自己困死，从不占地、从不圈地。
 - 教训：可达空间启发式反而把自己引向死角；纯移动不增加占地（前 8 回合生长窗口之外，蛇头进一格蛇尾退一格，净占地 0）。

 ### v2：加生存硬门 + 外扩 + 机会性圈地
 - 改动：① 加 keep-alive 硬门——移动后可达空间必须 ≥ 蛇长+缓冲，否则拒绝；② 朝远离己方重心方向外扩占地；③ 能圈出≥6 格时直接封口固化。
 - 结果：对 sample_ai **1 胜 2 负**（seed2 以 [130,0] 大胜），分数从 16 提升到 24/130。但遇强敌（rank15 [0,198]）仍惨败。
 - 关键发现：人类靠 **分裂（split）** 拥有多条蛇，每回合能行动 4 次，而我始终只有 1 条蛇，行动次数被碾压（240 vs 1811 步）。单条蛇占地天花板约 1 格/回合。

 ### v3：分裂换行动次数 + 激进吃道具
 - 改动：① 蛇长≥8 且有空槽时主动 split；② 更激进吃增长道具（长度是分裂与圈地的前提）；③ 沿用 v2 的 keep-alive 硬门。
 - 结果：对 sample_ai **3:0 全胜**（[74,50]、[104,16]、[38,28]），分数大幅提升。对 rank15 仍 0:3，但比分接近（[22,60]、[14,76]、[48,66]），且均在 ~100 回合被吃掉。

 ## 当前瓶颈

 1. **早死**：对 rank15 ~60-105 回合就被消灭，keep-alive 门还不够稳（`reachable_space` 把己方蛇身当可走，会高估空间）。
 2. **圈地质量低**：人类能在中盘一次性圈掉 50-200 格，我只会被动封口，不会主动铺出 U 形路径再封口。
 3. **分裂后失控**：split 后的多条蛇各走各的，没有协同，容易被逐个击破。

 ## 下一轮计划（v4+）

 - 修 keep-alive 门：移动模拟时把己方蛇身当障碍（除即将让出的尾格），用多步前瞻而非单步 flood-fill。
 - 学人类的圈地套路：从人类回放里提炼「先沿边界铺一条长线→绕回封口」的条件行为（if-then skill）。
 - 分裂后做协同：多条蛇抱团圈大区域，而不是各走各的。
 - 接对手行为建模：记录「我走某步后对手的响应」，蒸馏成条件策略。
