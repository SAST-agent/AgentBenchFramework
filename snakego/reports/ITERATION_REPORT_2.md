 # SnakeGo 迭代报告 · 第 2 轮（v4 → v5 → v6）

 日期：2026-07-27
 承接第 1 轮（v1→v3）。本轮聚焦：为什么打不过 rank15 这种中等偏上人类。

 ---

 ## 量化战绩（每版本对每个对手 3 个 seed，side=0）

 ```
 ver  opponent   胜/有效/总
 v1   sample_ai  0/2/2          ← 全败，只活43步
 v3   sample_ai  3/3/3          ← 横扫
 v4   sample_ai  3/3/3  (184/224/46 分)
 v5   sample_ai  3/3/3  (60/170/38 分)
 v6   sample_ai  3/3/3  (178/108/62 分)   ← 最稳
 v4   rank15     0/3/3  (38/56/0 分)
 v5   rank15     0/3/3  (22/24/18 分)     ← 过激反而更差
 v6   rank15     0/3/3  (38/56/0 分)
 ```

 结论：对 sample_ai 已稳定碾压（v3 起全胜，v6 最稳，单局最高 184 分）。
 对 rank15 仍 0 胜，但分数从 v1 的个位数提升到 38-56，进入同一量级。

 ## 本轮三个版本做了什么

 ### v4：保守生存
 - 把 keep-alive 门的可达空间统计改成「所有蛇身都当障碍」（之前把自己蛇身当可走，会高估空间）。
 - 结果：对 sample 提升明显，对 rank15 活得更久但中盘仍被吃。

 ### v5：激进圈地
 - 早期就 split 到 4 条蛇 + 降低圈地阈值 + 主动贴自己身体造环。
 - 结果：对 sample 仍全胜，但对 rank15 反而更差（22/24/18 < v4 的 38/56）。教训：为行动次数牺牲了生存质量，短蛇更易被逐个击破。

 ### v6：平衡版（v4 生存 + v5 圈地）
 - 保留 v4 的保守分裂（>=10 长、<3 条、周围有 >=长+14 空间才 split），加上 v5 的「长蛇贴身体造环」圈地偏置。
 - 结果：对 sample 三局最稳（178/108/62，回合数高、分数高），但对 rank15 与 v4 持平——圈地偏置没来得及触发就被打死了。

 ## 瓶颈诊断（为什么还打不过 rank15）

 1. 生存仍是天花板：对 rank15 几乎都在 150-370 回合被吃掉某条蛇而崩盘。单步 flood-fill 的 keep-alive 门不够，因为不预测对手下一步会把空间封死。
 2. 圈地质量差：人类能一次圈 50-200 格，我主要靠缓慢占地 + 偶发小圈地。主动造大环（沿边界铺 U 形再封口）还没实现。
 3. 分裂后无协同：多条蛇各走各的，没有「几条蛇配合圈一块大区域」的战术。

 ## 已知工程问题

 - rank09/rank13 对局在 ~26 回合报 ConnectionResetError：人类 AI 子进程崩溃。根因是我的引擎移植与 C++ adk 引擎在 split/seal 某条边界条件下状态分叉，导致人类模拟我的操作时判非法并 crash。sample/rank15 不受影响，能完整跑完。下一轮会先修这个分叉（重点查 seal_region 的 flood-fill 边界与 split 的蛇序），否则对顶级人类无法采集干净战绩。

 ## 下一轮计划（v7+）

 - 保命升级：把单步 keep-alive 换成 2-3 步前瞻模拟（minimax/随机 rollout），预测对手封路。
 - 修引擎分叉：定位 split/seal 的位级差异，恢复对 rank09/13 的干净评测。
 - 主动造大环：沿地图边界铺设长边再回封，一次圈大区域。
 - 多蛇协同：分裂出的蛇抱团圈同一区域。
 - 接对手行为建模：记录「我走 X 后对手走 Y」，蒸馏 if-my-then-rival 条件策略。
